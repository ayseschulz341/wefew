# Бар лжецов — Liar's Deck (веб-версия)

Веб-версия карточного режима **Liar's Deck** из игры *Liar's Bar*: блеф,
обвинения и русская рулетка за столом мрачного бара. Вы против 1–3 ИИ-ботов
с разными характерами — от напряжённой дуэли до полного стола из четырёх
игроков. Также доступна полноценная онлайн-партия на 2–4 друзей с комнатами,
приглашениями по ссылке, QR-коду и шестизначному коду комнаты.

Правила перенесены по канону (внутриигровые туториалы оригинала, наблюдения
геймплея и комментарии разработчиков; сводка —
[debigare.com](https://www.debigare.com/how-to-play-liars-deck-from-liars-bar-full-rules-and-variants/)).

## Правила «Карт лжеца»

1. **Колода — 20 карт**: 6 Дам, 6 Королей, 6 Тузов и **2 Джокера**.
2. У каждого игрока свой **шестизарядный револьвер**: **1 боевой патрон**
   и 5 пустых гнёзд, перемешанных **один раз** перед партией. Барабан больше
   не крутится — каждая осечка приближает выстрел: 1/6 → 1/5 → … → верный.
3. Отдельная **колода стола** (Дама/Король/Туз — равные шансы) задаёт
   **номинал раунда**, затем колода тасуется и каждому сдаётся **по 5 карт**.
4. В свой ход игрок за **30 секунд** выкладывает **от 1 до 3 карт** рубашкой
   вверх, заявляя номинал стола, либо кричит **«Лжец»** предыдущему игроку.
   **Джокер считается за любой номинал.**
5. Игрок без карт пропускает ходы. Если карты остались **только у одного**,
   он **обязан вскрывать** предыдущую выкладку.
6. При вскрытии открывается **только последняя выкладка** обвинённого:
   - есть лживая карта → к револьверу идёт **обвинённый**;
   - все карты честны → к револьверу идёт **обвинитель**.
7. Чем бы ни кончился спуск: если живых больше одного — **полная пересдача**.
   Новый раунд начинает **пойманный лжец**, а при ошибочном обвинении —
   **сам обвинитель**; если он погиб, начинает следующий живой.
8. **Последний живой за столом выигрывает партию.**

### Официальный вариант «Дьявол»

Ровно одна карта каждого номинала помечена. Когда её номинал стал номиналом
стола (и живых ≥ 3), она работает как **Дьявол**: её можно выложить только
одну, она честна — но при вскрытии к револьверам идут **все, у кого остались
карты, кроме самого обвинённого**.

## Запуск

```bash
npm install
npm run dev:server # API + WebSocket → http://localhost:8080
npm run dev        # в другом терминале: интерфейс → http://localhost:5173
```

Продакшен-сборка:

```bash
npm run build      # проверка типов + сборка в dist/
npm start          # сайт, API и WebSocket → http://localhost:8080
```

Тесты движка и ИИ:

```bash
npm test                                  # все тесты (vitest)
npm run test:online                       # два игрока, комната и первый сетевой ход
npm run test:stress                       # стресс: 200 партий в консоль
```

Визуальный обход (headless Chromium, скриншоты всех экранов и вьюпортов):

```bash
npm run test:visual
```

## Особенности реализации

- **Движок** — чистый редьюсер (`src/game/engine.ts`), 78 автоматических тестов
  (`src/tests/*.test.ts`): состав колоды и метки Дьявола, барабан как явная
  очередь гнёзд, лимит 1–3 карты, обязательное вскрытие последнего игрока
  с картами, исходы обвинений (только последняя выкладка), залп варианта
  «Дьявол», старт раунда по канону, инвариант сохранения всех 20 карт и
  стресс из случайных партий в обоих режимах.
- **ИИ-боты** (`src/game/ai.ts`, характеры в `src/game/characters.ts`) —
  шесть полностью озвученных персонажей с характерами и репликами. Подозрение строится на
  честной байесовской модели с гипергеометрической оценкой осуществимости
  честной заявки: бот знает только публичную информацию (размеры заявок) и
  свою руку — чужие ранги он не подглядывает. Доказанная ложь вычисляется
  подсчётом вместимости номинала (8 диких карт на колоду минус свои).
  Бот осторожничает с опасным барабаном, добивает соперников на грани,
  а при верном спуске «тянет время» выкладками.
- **Звук** — эффекты синтезируются через WebAudio API, а голосовые реплики
  загружаются из `public/audio`. Взвод, подача гнезда, осечка и выстрел
  синхронизированы с анимацией револьвера.
- **Графика** — SVG-карты, отдельная красная карта Дьявола, аватары зверей
  и шестиступенчатая сцена револьвера (загрузка, взвод, барабан, прицел,
  спуск, исход); нуарная тема на CSS. Анимации —
  framer-motion.
- **Интерфейс** — таймер хода с полосой (отключается в меню), горячие
  клавиши (**1–5** выбор карты, **Enter** положить, **L** обвинить,
  **Esc** пауза), реплики персонажей, журнал партии, пауза с меню,
  статистика и настройки в localStorage, метка обязательного вскрытия,
  счётчик заявок на груде, индикаторы барабанов соперников.
- **Доступность** — aria-роли и live-области для статусов, видимый фокус,
  клавиатурное управление картами, поддержка `prefers-reduced-motion`.

## Онлайн-режим

- Один Node-процесс отдаёт собранный React-интерфейс, REST API и WebSocket
  `/ws` на одном домене. В production приглашения автоматически используют
  публичный HTTPS-адрес игры.
- Сервер авторитетно применяет ходы, таймеры, вскрытия и рулетку. Клиент не
  может прислать собственный результат или изменить чужое состояние.
- Каждому игроку отправляется персональная проекция: настоящая собственная
  рука, но только количество чужих карт; без колоды, закрытой стопки и порядка
  патронов. Результат спуска раскрывается только перед моментом выстрела.
- Сессия сохраняет место на 24 часа, WebSocket восстанавливается с
  экспоненциальной задержкой, а неподтверждённые игровые действия повторяются
  с тем же `actionId` и безопасно дедуплицируются сервером.
- Комната вмещает максимум четырёх игроков; начать можно при двух подключённых.
  Хост выбирает «Классику»/«Дьявола» и таймер: без ограничения, 15, 30, 45
  или 60 секунд.

## Развёртывание на Railway

Новые сервисы Railway автоматически используют Railpack; устаревшие
`railway.json` и `nixpacks.toml` проекту не нужны. Перед отправкой изменений
можно полностью проверить production-контур командой `npm run test:deploy`.

1. Создайте сервис через **New → Deploy from GitHub Repo** и выберите репозиторий.
2. В **Settings → Build** оставьте **Railpack**. Он определит `npm run build` и
   `npm start` из `package.json`.
3. В **Settings → Deploy** установите **Healthcheck Path** = `/api/health`,
   **Healthcheck Timeout** = `100` и **Restart Policy** = `On Failure`.
4. В **Variables** добавьте `RAILWAY_DEPLOYMENT_DRAINING_SECONDS=15`, чтобы
   сервер успевал закрыть HTTP- и WebSocket-соединения перед остановкой.
5. В **Networking** нажмите **Generate Domain**, затем проверьте
   `https://ваш-домен/api/health`: ответ должен быть `{ "ok": true }`.

Переменные окружения для обычного same-origin развёртывания не нужны. При
использовании собственного публичного адреса до первого деплоя можно указать
`VITE_PUBLIC_APP_URL=https://ваш-домен` — именно он попадёт в QR и ссылки.

Комнаты хранятся в памяти процесса, поэтому Railway-сервис следует держать в
одной реплике. Активная партия переживает переподключение браузера, но не
перезапуск контейнера; для горизонтального масштабирования понадобится общий
Redis-слой комнат.

Для этого сервиса не подключайте Railway Volume: игра не хранит данные на диске,
а volume мешает бесшовной замене контейнера при следующем деплое.

## Мобильная версия

- Адаптив от 320 px: липкая панель руки под большой палец, кнопки с
  тач-целями ≥ 44 px, выдвижной журнал.
- Отдельная **ландшафтная вёрстка**: вся партия влезает без скролла,
  компактные капсулы игроков, стол и груда рядом.
- На телефоне игра запускается только после поворота в горизонтальный режим;
  при обратном повороте партия и таймер автоматически ставятся на паузу.
- `100dvh`, safe-area вырезов, отключён double-tap zoom, PWA-манифест
  (полноэкранный режим, иконка барабана).
